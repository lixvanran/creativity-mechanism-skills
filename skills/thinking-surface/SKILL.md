# 思维面扩展（Thinking Surface）

把「多想几个办法」变成一件**可核验**的事：让 Agent 真的走几条不同的路，并且能证明每条路被走过了。

> **本规程的每条设计都带实验依据**（`evals/RESULTS.md`，6 臂 × 7 题同题对打）。
> 依据里最要紧的一条：**给 Agent 预置的分支，明显优于让它自己现编分支**
> （覆盖 1.3–1.5 vs 0.72，同 n 配平口径）。所以本 skill 的核心资产是**面目录**，
> 不是"教它怎么思考"。

## 什么时候用

- 用户要**方案 / 设计 / 对策**，且存在多条可行解法路径；
- 当前方案偏薄，或反复在同一思路上打转；
- 多个"不同思路"其实只是同一思路换了措辞。

**不要用**：答案唯一的题（可多解且多解都对的计算/事实题）、纯资料检索、纯格式转换、用户已指定唯一做法时。
> 理由：路径唯一时硬造分叉，产出的是噪声。负对照实验里，路径唯一的题上不该出现任何展宽。

## 先记住这三条（实验打出来的）

1. **「请从多个角度想一下」几乎没用。** 一次调用要 4 个角度，覆盖 0.44，与基线 0.39 几乎相同——但 token 花掉了。想扩宽思维面，**必须真的分头走**。
2. **现编的框架质量明显低于给定的框架。** 让 Agent 自己测绘决策点，覆盖 0.72；从面目录里挑，覆盖 1.3–1.5。⇒ **先查目录，别现编。**
3. **"说得不一样"不等于"想得不一样"。** 各臂之间措辞层面的差异都很大（余弦距离 0.91–0.94，无判别力），但只有覆盖任务真实分叉点的臂才算真的宽了。

## 核心区分

| | 换身份 | 换路径 |
|---|---|---|
| 改什么 | 生成者的身份先验 | 决策点上取哪一支 |
| 产出差异 | 同一路径的不同说法 | 真的走了不同的路 |
| 可核对吗 | 难 | **易**（走这条路必会留下标记） |
| 本 skill 怎么用 | 不用（实测不占优） | **主路径** |

## 四步规程

### 1. 选轴（从面目录挑，别现编）

打开 `references/path-recipes.md` 的**路径轴库**，按任务类型挑 **3-5 条**候选轴。

挑选规则：
- 优先选**任务型轴**（内容/关系/激励/载体/规则/时间/匹配/资源/试点/兜底/利益方/逆向）；
- 选完把它们**改写成这道题的具体做法**（"以阅读社群为中心" → "每班四人共读小组，每天一个争议问题"）；
- **把"轴"翻译成本题语言的过程本身就是增益**，别原样照抄。

若目录里确实没有合适的轴，才自测绘（见 §自测绘兜底），且**必须**事后回测真伪分叉。

### 2. 签路径（签名必须先于生成写死）

为选定的 k 条路径各写一组**签名**：

- **正签名**：2 个只有真走这条路才会在答案里出现的、**具体可观察**的要点。写名词或动作。
  - 好：`每班固定四人共读小组`、`每周一次跨班圆桌`
  - 坏：`重视同伴关系`、`营造氛围`（空话，恒真）
- **反签名**：这条路上**不该出现**的东西（识破"嘴上说说"和"跑偏了"）。
  - 例：路径是「激励赛制」⇒ 反签名 = `以阅读会与共读为主要机制`（说明它其实走的是关系路线）。

**签名必须在生成前写死**。生成完再补签名 = 自证，一律作废。

每条路径还要写**代价**：这条路牺牲什么、谁会不满意。
> 不写代价的路径不是路径，是"全都想要"——四条这样的路径会高度重合，白跑。

### 3. 分头走（隔离生成）

- 每条路径**独立**生成，互相看不见对方的产出；
- 每条路径的提示里只放它自己的 brief + 签名要点；
- **不要**在一条输出里同时想多条路（那样量出来的"宽度"是自己造的）；
- 生成时**不写**"我换个角度再想想"这类表演性表述（会被审计判为反签名）。

### 4. 核对与合流（保留分歧）

1. **核对**：用签名逐条核对产出。**只提一句签名不算兑现**——必须看到对应的实际做法。
2. **处置**：兑现不了的路径，作废或按缺口重走；记兑现率。
3. **合流**：**保留分歧**，不要取交集、不要投票、不要"综合最优"。
   - 合流输出 = 每条路径的方案 + 它覆盖的决策点 + 它的代价 + **它们之间真正的冲突点**。
   - 冲突点是资产：它告诉用户"你在这儿必须选一个"。投票会把思维面收回去。

## 自测绘兜底（弱路径，慎用）

只有当面目录没有合适轴时才用。**必须**按 `references/fork-map.md` 的规程写决策点地图，
且**必须**在生成后回测：用各路径的机制骨架两两比对，重合度高 ⇒ 这两条其实是同一条路，合并并如实写。

> 实测：自测绘分支的覆盖（0.72）明显低于从目录里挑（1.3–1.5）。它不是不能用，是**别当默认路径**。

## 单路径模式（本题无可分叉点时）

不要硬造分叉。改为：
1. 明说"这题的解法路径基本唯一"；
2. 把力气花在**代价、边界、失败模式**上；
3. 如果用户坚持要多个方案，**明说**这些方案属于同一路径的不同参数，不是不同路径。

## 输出格式（默认）

```
【选轴】   选了哪几条轴（来自目录/自测绘）、每条在本题的具体做法、代价
【签名】   每条路径的正签名 + 反签名
【分头产出】每条路径的方案（标明走了哪条路径）
【核对】   逐条：兑现 / 未兑现 + 缺口
【合流】   保留分歧的整合 + 冲突点 + 待用户拍板项
```

## 硬规则（实验打出来的坑）

1. **先查目录，别现编。**（现编覆盖 0.72 vs 给定 1.3–1.5）
2. **别用"一句话多角度"糊弄。**（覆盖 0.44 ≈ 基线 0.39）
3. **换身份 ≠ 换路径。** 让人设不同大概率只改说法。
4. **签名要具体。** 名词/动作，不是形容词。
5. **签名先于生成。** 事后补签名 = 自证。
6. **只提一句不算兑现。** 审计看的是"实际做法"，不是"出现了这个词"。
7. **别在一条输出里塞多条思路。** 会把自己的思维面量高。
8. **合流不许投票/取交集。** 投票把宽度收回去。
9. **每条路径都要写代价。** 没代价的路径会互相重合。
10. **路径唯一就别造分叉。** 那是噪声，报告时如实写「本题无可分叉点」。
11. **审计者不看生成者的自述。** 自己说自己走了不算数。
12. **给出信息，给出余地。** 不要把轴写死到只剩一种走法。
13. **别复述模型本来就会做的事。** 本 skill 只提供"换路径"，不讲怎么写方案。
