## 2. ★ v2 的四步规程（★ 与 v1 的差异高亮 ★）

### 步骤 1（★ 新增 ★）：列实体类别

在选轴**之前**先想清楚：**这道题里有哪些"可核验的对象类别"？** 每类给 2–3 个具体例子。

> 例（选校题）：院校体系层次（985/211/双一流）、专业与学科实力（第五轮评估 A 类）、城市与产业生态、费用与性价比、分数位次、培养模式、境外与港澳。

★ **为什么这一步是关键**：
- 它把"域内"从**事后检查**变成**前置生成** ⇒ ⇒ 跨域分支（"进大厂"）在这一步就不会出现；
- 它**不依赖任何外部现成清单** ⇒ ⇒ skill 在任何题上都能用（外部清单只是加分项）；
- 它是**缺席诊断的运行时代理**（§3）。

### 步骤 2（★ 改写 ★）：双轨取轴

- **轨 A**：从 `references/path-recipes.md` 的轴库挑 3–5 条（★ 过程轴 ★）
- **轨 B**：从步骤 1 的实体类别里挑（★ 实体域轴 ★）
- 合并去重（同一件事两种说法 ⇒ 合并），★ 别贪多，总共 3–5 条 ★

### 步骤 3（★ 强化 ★）：落地性闸门 + 签名

- **落地性闸门（U1）**：每条轴必须能落到步骤 1 的某个实体类别上。**落不上去 ⇒ 这条轴不成立**（它是跨域轴或伪轴）。
- **签名（U3）**：正签名 2 个（只有真走这条路才出现的、具体可观察的要点；写名词或动作）+ 反签名 + 代价。★ 签名与轴库无关，**始终先于生成写死** ★

### 步骤 4（不变，★ 已验证 ★）：隔离生成 + 保留分歧

各路径独立生成（互不可见）⇒ 用签名逐条核对（只提一句不算兑现）⇒ **合流保留分歧**（不投票、不取交集），冲突点是资产。

## 3. ★ 缺席诊断：v2 的"自检"能力（★ 范式变化 ★）

★ 关键发现（选校题实测，n=30）：**塌缩的形态不是"想得少"，是"够不着某些维度"** —— D3 连**提到**都只有 1/30。

⇒ ⇒ ★ **v2 不该只"帮 Agent 想更多"，而该"帮 Agent 发现自己压根没想什么"** ★

⇒ **机制**：步骤 1 的实体类别表 = **候选维度表（判据的分母）** ⇒ ⇒ 生成后跑一遍：

```
对每个实体类别：答案里有没有可核验的实体落到它？
  覆盖 ⇒ 记
  缺席 ⇒ ★ 显式报出来：「这几个类别你一条都没碰」
```

⇒ ⇒ ★ **输出多一段【缺席自检】**：哪些角度压根没被想。
⇒ ⇒ 这对 skill 本身也是**自我度量**：它能报告"这次展开得够不够"。

★ 边界（★ 诚实 ★）：
- 缺席自检的**判据依赖实体类别表的完备性** ⇒ 表不全 ⇒ 误报"缺席"。
- ⇒ ⇒ **正确用法**：skill 自己列的类别表**是候选集**，不宣称"完备"；外部有清单时（★ 选校题有 211/985 名单 ★）⇒ **以外部清单为准**，skill 自举的表只作补充。
